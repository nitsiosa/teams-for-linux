# Security and privacy review of the fork's changes

Reviewed 2026-10-21 through `2fffbdda`. Product code and assets changed in ten commits since upstream `39ac73bb`: the four Wayland/media commits, `084eca21` (branding), and Pearl Luxe commits `436bc85d`, `95d517f7`, `fb989e39`, `93931589`, `2fffbdda` (72 product files, +3021/-171). This is an engineering review, not the enterprise security review upstream's README asks for before corporate deployment.

## Findings

| Change | Risk considered | Assessment | Evidence |
|---|---|---|---|
| `wayland.portalPicker` drops `--use-fake-ui-for-media-stream` on native Wayland (`cf91da0a`) | Camera and microphone requests could be denied or newly auto-granted | No change in effect. The app registers no permission request or check handler, so Electron's default approves media requests with or without the switch. Screen capture now starts only after the user picks a source in the portal dialog; before, `getDisplayMedia` resolved before the pick | `grep` for `setPermissionRequestHandler`, `setPermissionCheckHandler`, `setDevicePermissionHandler` in `app/`: none. Probe: camera and microphone granted in both modes |
| Portal picker display-media handler (`app/screenSharing/portalPicker.js`) | Capturing a source the user did not choose; stacked dialogs | Shares only when the portal returns exactly one source; zero or several sources reject the request; a request arriving while a dialog is open is rejected. It does not check `request.frame`, the same as the existing in-app picker; every share still needs the user's pick in the system dialog | 7 unit tests; probe runs with screen, window and cancel picks |
| Handler and startup logs | PII in logs | Fixed messages plus Electron's error text (`Failed to get sources.`); no source names, titles, paths or account data | Code review; probe app logs |
| Opt-in "Teams for Linux (Wayland)" desktop entry (`2c9cc7dd`, `9d557739`) | Escaping the AppArmor profile or the Chromium sandbox; hijacking deep links | Starts the same `/opt/teams-for-linux/teams-for-linux` path the profile attaches to; adds only `--ozone-platform=wayland --wayland.portalPicker=true`; no `--no-sandbox`; no `MimeType`, so `msteams:` links keep going to the default entry | `.deb` inspection; unit test `waylandDesktopEntry.test.js` |
| Package contents | Changed permissions or shipped test/design data | Binary and `chrome-sandbox` `755` as before (postinst sets `4755` only without user namespaces); the new desktop file is `664` root-owned like upstream's generated entry; `app.asar` holds no `tests/` or `docs/design/` files | `dpkg-deb -c`; final `@electron/asar` listing (2695 entries, 0 tests, 0 design docs) |
| Startup diagnostics (`app/screenSharing/waylandPrerequisites.js`) | Information disclosure, slow or risky startup work | Reads environment variables, checks for files under `XDG_DATA_DIRS` and reads small `.portal` files; no subprocesses, D-Bus calls or network; messages carry no paths; skipped inside Flatpak and snap | 8 unit tests, including one that keeps user paths out of messages |
| Test-only probe (`tests/manual/waylandShareProbe.mjs`) | Leaking screen or camera content; weakening the shipped app | Not shipped. Runs the checkout with `--no-sandbox` and `E2E_TESTING` only on a developer desktop; reduces captured frames to brightness numbers inside the renderer; never listens to the microphone; reads only ScreenCast portal traffic during a run and saves nothing | Code review; asar listing |
| Harbour Huddle application artwork (`084eca21`) | Malformed image input, executable SVG content, or unlicensed public assets | Supplied PNGs are fixed square dimensions; missing 96px/1024px variants are deterministic resizes; unit tests pin every packaged size and SHA-256 and require runtime copies to match. The SVG has no scripts, event handlers or external references and is tracked as source rather than shipped. The fork maintainer explicitly confirmed ownership or permission to publish it | 3 icon integrity tests; clean `.deb` build; every hicolor and runtime icon compared byte-for-byte with package/asar; publication-rights confirmation on 2026-10-21 |
| Pearl Luxe design assets and generator (`436bc85d`) | Remote resources, incomplete Night tokens, unsafe selectors or generated-output drift | Pinned handoff SHA-256; JSON is the token source; generated adaptive/Night/wrapper CSS has no URL or `@import`; tests enforce complete token inheritance, identical Light/Night rules, AA normal-text contrast and reproducibility | `pearlLuxeGeneration.test.js`; generated-output drift check |
| Forced default migration (`95d517f7`) | Loss of an existing theme choice or disclosure of credentials stored in `config.json` | Runs once; writes `config.pre-pearl-luxe-v1.json` before modifying config; preserves target mode and symlinks; uses exclusive backup creation and atomic config replacement; logs no values or paths; later choices are respected | 6 migration tests plus custom-theme E2E restart flow |
| Live selector audit (`95d517f7`, `2fffbdda`) | Exposing signed-in Teams content | Audit returns only anonymised page/frame indexes, selector counts, safe static structural IDs/classes, computed CSS, geometric bounds and contrast ratios. It disables screenshots/traces/video and never returns URLs, text, HTML, attributes with dynamic values, accessibility trees, console or network data. Raw sanitized JSON contains no URL/email markers | `tests/manual/pearlLuxeSelectorAudit.mjs`; `docs/design/pearl-luxe/selector-audit.json` |
| Wrapper reskin and injected overlays (`fb989e39`, `93931589`) | Widening renderer privileges or crossing prompt/profile boundaries | Passive local CSS only; every preload, partition and IPC contract remains separate; injected overlay selectors are restricted to wrapper-owned IDs; no new IPC; forced Night mode reaches local pages through a validated `light|dark|auto` query rather than `nativeTheme`, so native surfaces remain untouched | Wrapper inventory and injected-style unit tests; 28 network-blocked synthetic screenshots |
| App-wide Pearl colours and Teams dark under forced Night (after `15a28d2e`) | Theming views outside the audit; unreadable text; new main-to-renderer messages | Colour tokens only, on `:root` and Fluent providers, and a unit test keeps that block to `--lx-*` token references; geometry stays chat-scoped; every Pearl pairing passes AA in both modes. Forced Night reuses the existing `system-theme-changed` channel and value type, so no IPC is added. Sign-in pages and Office documents are other origins and receive no CSS. The live call stage now inherits the colours | Unit tests, hidden-window provider probe, E2E 17/17 |
| Aggressive chat geometry (`2fffbdda`, narrowed afterwards) | Teams selector drift, small-window or call-stage regressions | User explicitly approved layout overrides. Rules are restricted to live-audited chat/list/composer IDs and exact audited Fluent classes; sign-in, calls/meetings, attachments absent from the audit, portal and native UI are not selected. The page grid, app rail and chat-list row geometry were withdrawn after they hid the rail and overlapped list rows in the installed build; unit tests now reject grid-template and position declarations and row geometry on chat-list items | Count-only audit, privacy-masked geometry comparison, full E2E, final package smoke |

Nothing in these changes adds IPC channels (so `app/security/ipcValidator.js` is unchanged), touches `contextIsolation`, `nodeIntegration` or `sandbox`, adds network endpoints, or adds dependencies.

## Pre-existing risks, unchanged by the fork

- `contextIsolation` and the renderer sandbox are off for the Teams windows so injected scripts can reach the Teams DOM (upstream README warning).
- With no permission handler, Electron approves every permission request from Teams web content (camera, microphone, notifications and others).
- Electron cannot start sandboxed from a source checkout on Ubuntu 24.04 (`kernel.apparmor_restrict_unprivileged_userns=1`); local tests use `--no-sandbox`, while the installed `.deb` keeps the sandbox through its AppArmor profile.
